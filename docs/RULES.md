# RULES — Антиспам правила та філософія

## Основна філософія

**Ми не спамимо. Точка.**

Кожна взаємодія має бути:
- ✅ Персоналізована
- ✅ Релевантна
- ✅ Цінна для отримувача
- ✅ Одноразова

---

## Ключові правила

### 1. Один контакт = Один раз

```
leads.invited = True
├─ ніколи не повторюємо запрошення
├─ БД відслідковує всіх контактованих
└─ Rules.py перевіряє перед запрошенням
```

**Реалізація:**
```python
if rules.can_invite(contact_id):
    inviter.send_invite(contact_id)
    rules.mark_invited(contact_id)
```

---

### 2. Ліміти на день (anti-flood)

| Канал     | Дія             | Ліміт |
|-----------|-----------------|-------|
| LinkedIn  | Публікації      | 2 |
| LinkedIn  | Дії (всього)    | 50 |
| Telegram  | Публікації      | 5 |
| Telegram  | Запрошення      | 10 |
| Instagram | Публікації      | 3 |
| Instagram | Follows         | 8 |
| Instagram | DMs             | 8 |

---

### 3. Затримки між діями

| Дія          | Затримка | Причина |
|--------------|----------|---------|
| Публікація   | 1 година | Не виглядати ботом |
| Запрошення   | 5-10 хвилин | Людське поведінка |
| Збір даних   | 1 хвилина | Не перенавантажувати сервер |

---

### 4. Персоналізація обов'язкова

**Запрошення НІКОЛИ не буде:**
```
❌ "Hey, follow me"
❌ "Check out my profile"
❌ "Привіт! Я цікавлюся вашою компанією, давайте спілкуватися"
```

**Запрошення МАЄ бути:**
```
✅ "Hi, I noticed you're interested in B2B automation. 
   We just published a guide on operationalRisks..."
✅ "Привіт! Твої коментарі про compliance дуже цікаві. 
   Поділилися б статтею про автоматизацію compliance?"
```

## Антиспам механізми

### В коді

**rules.py**
```python
can_invite() → перевіряє БД
check_daily_limit() → лічить дії за день
log_action() → логує всю взаємодію
```

**scoring.py**
```python
score_lead() → визначає SAVE / INVITE / SKIP
```

**models.py**
```python
Lead.invited = True → навіки позначити
Action.action_type → трасування всього
```

### В БД

Кожна дія логується:
```sql
INSERT INTO actions (
    action_type, channel, lead_id, 
    details, created_at
) VALUES (...);

-- Перевірка чи контакт вже був запрошений
SELECT * FROM leads WHERE id = ? AND invited = True;
```

## Політика для кожного каналу

### LinkedIn

- ❌ **Ніяких DM** (поточні правила платформи)
- ✅ **Тільки публічні пости**
- ✅ **Коментарі як engagement**
- ✅ **Лінки на інші канали для контакту**

### Telegram

- ✅ **Один раз в DM на людину**
- ✅ **Тільки якщо релевантно** (score >= threshold)
- ✅ **Персоналізоване повідомлення**
- ✅ **Затримка 5 хвилин між запрошеннями**

### Instagram

- ✅ **Follow без гарантії контакту**
- ✅ **Один DM на людину максимум**
- ✅ **Тільки після аналізу профілю**
- ✅ **DM повинна бути цінною, не спамом**

## Що робити, якщо

### Якщо лід блокує тебе
```
Mark: blocked = True
Action: skip_future = True
Логування: "User blocked us"
```

### Якщо лід жалується на спам
```
Mark: reported_spam = True
Action: НІКОЛИ не контактувати знову
Log: включити в anti-spam чорний список
```

### Якщо ліміт перевищений
```
Scheduler: подати помилку в лог
Action: SKIP решту запрошень на день
Alert: адміністратор повинен перевірити
```
